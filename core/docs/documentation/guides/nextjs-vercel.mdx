This guide demonstrates how to use vaultix to manage secrets for your Next.js + Vercel stack from local development to production. It uses:

- vaultix (you can use [vaultix Cloud](https://app.vaultix.com) or a [self-hosted instance of vaultix](https://vaultix.com/docs/self-hosting/overview)) to store your secrets.

## Project Setup

To begin, we need to set up a project in vaultix and add secrets to an environment in it.

### Create a project

1. Create a new project in [vaultix](https://app.vaultix.com/).

2. Add a secret to the development environment of this project so we can pull it back for local development. Select the **Development** environment from the environment selector, then click **Add Secret** and add a secret with the key `NEXT_PUBLIC_NAME` and value `YOUR_NAME`.

3. Add a secret to the production environment of this project so we can sync it to Vercel. Switch to the **Production** environment and add a secret with the key `NEXT_PUBLIC_NAME` and value `ANOTHER_NAME`.

## Create a Next.js app

Initialize a new Node.js app.

We can use `create-next-app` to initialize an app called `vaultix-nextjs`.

<Tabs>
    <Tab title="JavaScript">
        ```console
        npx create-next-app@latest --use-npm vaultix-nextjs
        cd vaultix-nextjs
        ```
    </Tab>
    <Tab title="TypeScript">
        ```console
        npx create-next-app@latest --ts --use-npm vaultix-nextjs
        cd vaultix-nextjs
        ```
    </Tab>
</Tabs>

Next, inside `pages/_app.js`, lets add a `console.log()` to print out the environment variable in the browser console.

<Tabs>
    <Tab title="JavaScript">
    ```js
    import '@/styles/globals.css'

    export default function App({ Component, pageProps }) {
        console.log('Hello, ', process.env.NEXT_PUBLIC_NAME);
        return <Component {...pageProps} />
    }
    ```
    </Tab>
    <Tab title="TypeScript">
    ```tsx
    import '@/styles/globals.css'
    import type { AppProps } from 'next/app'

    export default function App({ Component, pageProps }: AppProps) {
        console.log('Hello, ', process.env.NEXT_PUBLIC_NAME);
        return <Component {...pageProps} />
    }
    ```
    </Tab>
</Tabs>

## vaultix CLI for local development environment variables

We'll now use the vaultix CLI to fetch secrets from vaultix into your Next.js app for local development.

### CLI Installation

Follow the instructions for your operating system to install the vaultix CLI.

<Tabs>
   <Tab title="MacOS">
  	Use [brew](https://brew.sh/) package manager

    	```console
    	$ brew install vaultix/get-cli/vaultix
    	```
   </Tab>
   <Tab title="Windows">
      Use [Scoop](https://scoop.sh/) package manager

        ```console
        $ scoop bucket add org https://github.com/vaultix/scoop-vaultix.git
        ```

        ```console
        $ scoop install vaultix
        ```
   </Tab>
	 <Tab title="Alpine">
	 Install prerequisite
		```console
		$ apk add --no-cache bash sudo wget
		```

    	Add vaultix repository
    	```console
    	$ wget -qO- 'https://artifacts-cli.vaultix.com/setup.apk.sh' | sudo sh
    	```

    	Then install CLI
    	```console
    	$ apk update && sudo apk add vaultix
    	```

   </Tab>
	 <Tab title="RedHat/CentOs/Amazon">
	 Add vaultix repository
		```console
		$ curl -1sLf \
		'https://artifacts-cli.vaultix.com/setup.rpm.sh' \
		| sudo -E bash
		```

    	Then install CLI
    	```console
    	$ sudo yum install vaultix
    	```

   </Tab>
	 <Tab title="Debian/Ubuntu">
	 	Add vaultix repository

		```console
		$ curl -1sLf \
		'https://artifacts-cli.vaultix.com/setup.deb.sh' \
		| sudo -E bash
		```

    	Then install CLI
    	```console
    	$ sudo apt-get update && sudo apt-get install -y vaultix
    	```

   </Tab>
	<Tab title="Arch Linux">
		Use the `yay` package manager to install from the [Arch User Repository](https://aur.archlinux.org/packages/vaultix-bin)

		```console
		$ yay -S vaultix-bin
		```

   </Tab>
</Tabs>

### Login

Authenticate the CLI with the vaultix platform using your email and password.

```console
$ vaultix login
```

### Initialization

Run the `init` command at the root of the Next.js app. This step connects your local project to the project on the vaultix platform and creates a `vaultix.json` file containing a reference to that latter project.

```console
$ vaultix init
```

### Start the Next.js app with secrets injected as environment variables

```console
$ vaultix run -- npm run dev
```

If you open your browser console, **Hello, YOUR_NAME** should be printed out.

Here, the CLI fetched the secret from vaultix and injected it into the Next.js app upon starting up. By default,
the CLI fetches secrets from the development environment which has the slug `dev`; you can inject secrets from different
environments by modifying the `env` flag as per the [CLI documentation](/cli/usage).

At this stage, you know how to use the vaultix CLI to inject secrets into your Next.js app for local development.

## vaultix-Vercel integration for production environment variables

Use our [Vercel Secret Syncs](../../integrations/secret-syncs/vercel) guide to sync secrets from vaultix to Vercel as production environment variables.

At this stage, you know how to use the vaultix-Vercel integration to sync production secrets from vaultix to Vercel.

<Warning>
  The following environment variable names are reserved by Vercel and cannot be
  synced: `AWS_SECRET_KEY`, `AWS_EXECUTION_ENV`, `AWS_LAMBDA_LOG_GROUP_NAME`,
  `AWS_LAMBDA_LOG_STREAM_NAME`, `AWS_LAMBDA_FUNCTION_NAME`,
  `AWS_LAMBDA_FUNCTION_MEMORY_SIZE`, `AWS_LAMBDA_FUNCTION_VERSION`,
  `NOW_REGION`, `TZ`, `LAMBDA_TASK_ROOT`, `LAMBDA_RUNTIME_DIR`,
  `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN`,
  `AWS_REGION`, and `AWS_DEFAULT_REGION`.
</Warning>

## FAQ

<AccordionGroup>
    <Accordion title="Why should I use vaultix if I can centralize all my Next.js + Vercel environment variables across all environments directly in Vercel?">
        Vercel does not specialize in secret management which means it lacks many useful features for effectively managing environment variables.
        Here are some features that teams benefit from by using vaultix together with Vercel:

        - Audit logs: See which team members are creating, reading, updating, and deleting environment variables across all environments.
        - Versioning and point in time recovery: Rolling back secrets and an entire project state.
        - Overriding secrets that should be unique amongst team members.

        And much more.
    </Accordion>
    <Accordion title="Is opting out of end-to-end encryption for the vaultix-Vercel integration safe?">
        Yes. Your secrets are still encrypted at rest. To note, most secret managers actually don't support end-to-end encryption.

        Check out the [security guide](/internals/security).
    </Accordion>
</AccordionGroup>
