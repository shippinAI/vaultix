This quickstart guide walks you through the recommended secrets management workflow for local development. You'll create a [project](/documentation/platform/secrets-mgmt/project), add secrets to one of its environments, and inject them into your local application using the [vaultix CLI](/cli/overview), all without needing a `.env` file.

<Info>
Prerequisites:

- An vaultix account on [vaultix Cloud](https://app.vaultix.com) or a [self-hosted instance](/self-hosting/overview)
- The [vaultix CLI](/cli/overview) installed for your platform
- An application or script you run locally
</Info>

<ConfigureProject />

## Step 2: Connect your app to vaultix

Now that you've set up a project that holds your secrets in vaultix, you can connect your application and give it access to those secrets at runtime.

### Authenticate with the CLI

Authenticate with the vaultix CLI by running [`vaultix login`](/cli/commands/login):

```bash
vaultix login
```

This prompts you to select your hosting option, then opens your browser to complete the login.

<Note>
  In a containerized environment such as WSL 2 or Codespaces, run `vaultix login -i` to avoid browser-based login.
</Note>

### Connect your project

Next, connect your application to your vaultix project:

<Steps>
  <Step>
    In your application's directory, link it to the vaultix project you created by running [`vaultix init`](/cli/commands/init):

    ```bash
    vaultix init
    ```
  </Step>
  <Step>
    Follow the prompts to select the organization/project where you created your secrets earlier. This writes a `.vaultix.json` file to your project with [local project settings](/cli/project-config):

    ```json .vaultix.json
    {
      "workspaceId": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
      "defaultEnvironment": "",
      "gitBranchToEnvironmentMapping": null
    }
    ```

    <Note>
    `.vaultix.json` files contain no secrets and are safe to commit to version control systems like git.
    </Note>
  </Step>
</Steps>

## Step 3: Inject secrets into your app

Now that your vaultix project is configured within your application, vaultix can provide the secrets.

Start your application by wrapping its start command with [`vaultix run`](/cli/commands/run):

<CodeGroup>
  ```bash Node.js
  vaultix run --env=dev -- npm run dev
  ```

  ```bash Flask
  vaultix run --env=dev -- flask run
  ```

  ```bash Go
  vaultix run --env=dev -- go run main.go
  ```
</CodeGroup>

vaultix fetches the secrets and injects them as environment variables. This lets your application read the secrets from its environment at runtime.

<Check>
  You can now manage your application's secrets through vaultix without needing a `.env` file.
</Check>
