Read root AGENTS.md and the folder context. Apply costar-alignment,
grounded-delivery, implementation-verification and project-journaling. Infer
already-recorded intent; ask only a focused unresolved product choice. This skill
does not authorize deployment, credential handling or a new integration.

Read `docs/0114-domain-scripted-ui-standard.md`, the relevant 0076 packet,
`contracts/vaultix.ui-actions.v1.schema.json` and `docs/interaction/workflows.json`.
Use the existing capability domain IDs; distinguish public, auth and tenant surface.
Load only the relevant domain implementation, plus its actual API/store/permission
dependencies. Read complete modules before editing; a file inventory is not review.

Port a complete existing workflow in place. Preserve correct behavior, validation,
access requests, encrypted persistence, failure recovery and human controls. Extract
a shared feature handler only when needed; do not create a second AI implementation
or call a proxy a completed native migration. Keep product names/contracts Vaultix.

Map each meaningful control to an authored action or explicit human-only boundary.
Use exact typed metadata inputs, source permission references, mounted view scope,
target and definition version. Reuse handlers for pointer, keyboard and scripts.
No credential/value serialization, model-authored selectors/code, global DOM replay
or discovery-as-authorization. Give help, dialogs and progress accessible semantics;
retain reduced motion, focus restoration and takeover. Never confuse lesson completion,
accepted intent, service success and viewport acknowledgement.

Author short finite scripts from known same-domain actions. A future MCP consumer
discovers domain tools progressively through standard interfaces; it cannot install
new handlers. Public examples cannot satisfy tenant proof. Keep planned/local/remote
evidence distinct; the current schema deliberately permits no remote admission.

Before accepting a packet, compare the original capability baseline, ledger and
actual changed handlers. Exercise real success, denial, invalid/stale scope and
recovery; challenge coverage with a deliberately removed binding. For remote work
include real client/browser pairing, replay, revocation and takeover races. For
mutations independently inspect persisted state and lost-response reconciliation.
Keep image, provider, fixture and manual evidence separate. Run the standard's
checker and compatibility tests, plus the changed workflow's canonical image checks.

Measure token and resource savings against equivalent browser tasks, including
failures and setup. Do not copy another system's percentage or estimate tokens from
bytes. Record source hashes, checks, gaps and exact next packet through the journal.
Update the partial ledger honestly; never promote all domains from one passing test.
